Title: Дельта-запросы

# Дельта-запросы

Дельта-запросы позволяют приложению получать только изменённые данные из базы данных. Поддерживаются дельта-запросы на уровне всей схемы данных, или на уровне поля `View` отдельного объекта схемы данных.

Для поддержки дельта-запросов схема данных или поле `View` должно содержать соотвествующий флаг:

Объявление схемы:

```cpp
db::Scheme _deltaTest = db::Scheme("scheme_with_delta", db::Scheme::Options::WithDelta);
```

Объявление поля:

```cpp
_scheme.define({

	...

	db::Field::View("refs", _refs, db::ViewFn([] (const Scheme &objScheme, const Value &obj) -> bool {
		...
	}), db::FieldView::Delta),

	...

});
```

Для использования дельта-запросов необходим дельта-токен - 64-битное целое число, характеризующее состояние БД на момент запроса, обычно - время начала изменяющего запроса.

При запросе к БД из приложения, это значение для поля передаётся в дополнительном поле `__delta` для каждого возвращённого объекта, нужно использовать максимальное значение из всех.

При запросе с помощью REST API готовое поле `delta` возвращается на одном уровне с `result`, других действий не требуется.

Дельта-токен можно использовать как с запросом без условий, так и с условными запросами. Для корректности работы системы, условия при выполнении дельта-запросов должно быть одинаковым.

## Выполнение дельта-запросов

```
// Для схемы
_objects.select(t,
	db::Query()
		.select("tsv", "some text").delta(deltaValue));

// Для View
_objects.select(t,
	db::Query::field(objectId, "viewField")
		.select("tsv", "some text").delta(deltaValue));
```

В REST API достаточно добавить поле `delta` к описанию запроса.

## Разбор данных

Дельта-запрос добавляет дополнительное поле `__delta` в запрос. Поле выглядит так:

```json
"__delta": {
	"action": <action>
	"time": <delta-token>
}
```

`<action>` принимает значения:

* `create` - объект был создан после последнего обновления
* `update` - объект был изменён после последнего обновления
* `delete` - объект был удалён после последнего обновления (только `__oid` будет в теле запроса)
* `append` - (не реализовано, сейчас помечается как `update`) - объект был добавлен во `View` после после последнего обновления
* `erase` - (не реализовано, сейчас помечается как `delete`) - объект был удалён из `View` после после последнего обновления

При прямом разборе результата запроса с помощью курсора (`db::ResultCursor`) в результате будут поля:

* `__d_action` - целочисленное значение, соответствующее `DeltaAction`
* `__d_time` - дельта-токен
* `__d_object` - идентификатор `__oid` объекта, используется вместо `__oid` в случае удалённого объекта
