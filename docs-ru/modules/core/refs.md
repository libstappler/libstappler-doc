# Ссылки и указатели

Здесь описаны ключевые особенности использования ссылок и указателей в Stappler SDK.

## Указатель: `Object *`

Простой указатель. В SDK используется, чаще всего, для связи с внешними интерфейсами.

* Позволяет модифицировать целевой объект.
* Может быть nullptr.
* Допускает арифметику
* Получатель не знает времени жизни

Если используется в качестве поля или параметра, означает слабую связь между объектами. Допустимо в случаях:

* Обратной связи с порождающим объектом (в таком случае, порождающий объект должен владеть порождённым)
* Другой гарантии существования объекта, на который указывает указатель, в течении всего требуемого времени
* Временных объектов

*Для новичков:*

* Арифметика работает в целых объектах, а не в байтах. Так, `++ptr` смещает указатель на один целый объект, или на `sizeof(*ptr)` байт.

* Возможно использование указателя как итератора для создания векторов, в таком случае для получения конечного итератора нужно прибавить к начальному длину блока в целых объектах (не байтах)

```cpp
Object *ptr = somedata;
size_t len = somelength;
Vector<Object> objects(ptr, ptr + len);
```

## Константный указатель: `const Object *`

Аналогично простому указателю, но не допускает изменения объекта, на который указывает. Допускает арифметику.

Кроме особенностей простого указателя:

* Данные, внедряемые в исполняемый код на этапе компиляции (в частности, строки, `const char *, const char16_t *`) имеют типы константных указателей. Пытаться изменять их недопустимо.

## Константная ссылка: `const Object &`

Ссылка для передачи гарантированно существующего объекта в качестве параметра.

* Не даёт модифицировать объект по ссылке.
* Не может быть nullptr - объект по ссылке всегда существует.
* Не допускает арифметики.
* Не может быть полем объекта.
* Гарантия времени жизни до конца вызова.

Особенности использования:

* Основное использование: для передачи параметра в функцию или для возврата всегда существующего значения:

```cpp
class Object {
public:
	void setField(const Field &f) {
		_field = f;
	}

	const Field &getField() const { return _field; }

protected:
	Field _field;
};
```

* Для малых объектов (размером до двух `uintptr_t` включительно) передача по константной ссылке не имеет смысл. Нужно заменить на передачу по значению, например:

```cpp

struct ObjectInfo {
	uint32_t intField;
	float floatField;
};

// Так делать не стоит
void function(const uint32_t &, const StringView &, const ObjectInfo &);

// Лучше так
void function(uint32_t, StringView, ObjectInfo);

```

* Конструирование нового объекта по ссылке с использованием auto вызывает копирование объекта!

```cpp
void function(const Object &obj, const Vector<OtherObject> &vec) {
	 // объект будет скопирован
	auto copy = obj;

	// а так - не будет, внимание на & после auto
	auto &subref = obj;

	// аналогично для циклов, здесь каждый объект на итерации будет скопирован
	for (auto it : vec) { }

	// а так - не будет, стоит писать именно так
	for (auto &it : vec) { }
}
```

* Брать указатель из ссылки возможно, но хранить такой указатель - плохая идея

## Обыкновенная ссылка: `Object &`

Используется, в первую очередь, для передачи объекта под выходной параметр.

* Объект по ссылке можно модифицировать
* Не может быть nullptr - объект по ссылке всегда существует.
* Не допускает арифметики.
* Не может быть полем объекта.
* Гарантия времени жизни до конца вызова.

Типичное использование:

```cpp
// Функция изменяет объект и возвращает статус успеха операции
Status function(Object &object) {
	// делаем работу и записываем результат в объект

	return Status::Ok;
}

Status doWork(size_t &counter) {
	Object object;

	// в процессе можем подсчитывать некоторое количество операций в counter
	auto status = function(object);
	if (status == Status::Ok) {
		// делаем что-то ещё
	}
	return status;
}
```

* Правила константной ссылки про auto действуют и на простую ссылку.
* Брать указатель из ссылки возможно, но хранить такой указатель - плохая идея.

## Перемещающая ссылка: `Object &&`

Предназначена для перемещения данных между объектами. Перемещение позволяет оптимизировать использование памяти, перемещая её из мест, где выделенная память больше не нужна, в места, где она будет использоваться. В первую очередь это касается контейнеров.

* Объект по ссылке можно модифицировать
* Не может быть nullptr - объект по ссылке всегда существует.
* Не допускает арифметики.
* Не может быть полем объекта.
* Получатель контролирует время жизни

Получая объект по перемещающей ссылке, функция получает контроль над его временем жизни. Объект, из которого выполнено перемещение, можно считать пустым, оставленным.

Для того чтобы перемещение сработало, объект справа от = обязан быть либо результатом работы функции, либо результатом `sp::move`.

Типичное использование:

```cpp
// Функция изменяет объект и возвращает статус успеха операции
Status function(Object &&object) {
	Object object = sp::move(object);

	// делаем работу

	return Status::Ok;
}

// Результат этой функции будет перемещён автоматически
Object makeObject() {
	return Object();
}

Status doWork() {
	// Здесь сработвет перемещение
	Object object = makeObject();

	auto status = function(sp::move(object));

	// здесь состояние object не определено

	return status;
}

Status doWork2() {
	// Так тоже сработает перемещение
	auto status = function(makeObject());

	return status;
}
```

## Контракт ненулевого указателя `NotNull<Object>`, `NotNull<const Object>`

Служит аналогично ссылке (`Object &`) и константной ссылке (`const Object &`), но позволяет сохранять полученный объект в указатель. Не даёт ошибочно передать nullptr.

* Объект по указателю можно модифицировать, если нет префикса const
* Не может быть nullptr - объект всегда существует.
* Не допускает арифметики.
* Не может быть полем объекта.
* Гарантия времени жизни до конца вызова.

В SDK в первую очередь используется для передачи объектов-наследников `Ref` в качестве параметров. Часто, для последующего их сохранения в `Rc<Object>`.

```cpp
class Object {
public:
	bool init(NotNull<SubObject> sub) {
		sub->function(); // Вызовет SubObject::function

		_subObject = sub;
		return true;
	}
protected:
	Rc<SubObject> _subObject;
};
```

## Умный указатель с подсчётом ссылок: `Rc<Object>`

Служит для автоматического контроля времени жизни объекта. Автоматически конвертируется в простой указатель при использовании.

* Объект по указателю можно модифицировать.
* Может быть nullptr, автоматически инициализируется как nullptr
* Не допускает арифметики.
* Объект жив, пока на него есть хотя бы один умный указатель.
* Требует, чтобы объект по указателю был наследником `Ref`

Также, даёт функции для конструирования объектов сразу внутри умного указателя:

```cpp
class Object : public Ref {
public:
	bool init(StringView name);
};

// Вызывает Object::init; если init возвращает false - вызов вернёт nullptr
Rc<Object>::create(StringView("name"));

struct Struct {
	Struct(StringViee name) noexcept;
};

// Вызовет конструктор, может вернуть nullptr только в случае нехватки памяти
Rc<Struct>::create(StringView("name"));
```

К умному указателю могут применяться ссылки, например, перемещающая ссылка (`Rc<Object> &&`). Это может быть использовано для оптимизации, когда владение умным указателем нужно передать в другой объект без цикла увеличения-уменьшения счётчика ссылок.

Использовать константные или простые ссылки по отношению к `Rc` лишено смысла.

Чаще всего, не выгодно использовать сам умный указатель в качестве параметра (это создаёт дополнительные вызовы увеличения и уменьшения счётчика ссылок), стоит использовать `NotNull<Object>` или `Object *`.
